## Snapshot boundary

The existing deployment uses program
`DzMTD92EwiEaZ5uTKPwweR2JEhp62kp8VEmpueCAQigr` and Config snapshot slot
`509605276`. `FEED_SNAPSHOT_SLOT` is an API X-ray setting only. There is no signer
environment variable that overrides Config's snapshot.

The intake reads Config on-chain, evaluates historical provenance at that slot,
and returns that slot in its response. The web checks it against its own Config
read. Buying for the first time after that snapshot fails `snapshot_not_held`.
Changing only the API setting to a slot after those purchases can change X-ray's
classification; it cannot make the real intake accept them.

The corrected local reader verified finalized slot `510033907`, after both
purchases at `510030133` and `510030143`. Each bag has 25,000,000,000 base units
at that later slot. This is a measured candidate for a separate test scenario,
not the Config snapshot of the existing deployment. Do not set the API to this
value while its intake and Config still use `509605276`.

A snapshot after new purchases is conforming only when it is the actual Config
snapshot of a new deployment. The existing season cannot be reset with
`SetSeason`: it requires `season_set == 0`. Existing eligible holdings and the
documented one-hop provenance path remain subject to the real intake checks.

Architect's decision: no snapshot override is permitted, including in local code
or a test harness. This proof must use the existing Config snapshot `509605276`
and the real intake service with its production validation rules on devnet.

`WEB_FLOW_MODES` belongs to the API, which serves `/api/web/config`. In a preview
build, omitted flows use demo adapters. Keep `feed`, `wallet` and `verify` live.

`RPC_URL` serves the public chain reads and transaction relay. `HELIUS_RPC_URL`
serves X-ray and web market reads. Set both explicitly to devnet. Using
`HELIUS_API_KEY` alone currently constructs a mainnet Helius URL regardless of
`CLUSTER`, so it is insufficient for this setup. `SOLANA_RPC_URL` does not replace
either setting here. `JUPITER_API_KEY` is optional for provider enrichment and
quotes; unavailable quotes remain unavailable.

The public API must contain no role keypair. Feed does not require a quote signer
or Rip/Sell flags. When both signer proxies are configured, their internal tokens
must differ.

## Intake and indexer

| Service | Additional variables                                                                                                                  |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| Intake  | `ROLE=intake-signer`, `INTAKE_SIGNER_KEYPAIR=<authorized role secret>`, `INTERNAL_TOKEN=<matching API token>`, `XRAY_SOURCE=fixtures` |
| Indexer | `ROLE=indexer`, `INDEXER_RPC_URL_FALLBACK=<devnet fallback RPC URL>`; optional `INDEXER_WS_URL=<devnet WebSocket URL>`                |

Intake's `RPC_URL` must support the enhanced `getTransactionsForAddress` history
contract as well as ordinary Solana RPC. The public Solana endpoint alone does
not supply that enhanced method. The signer injects this same RPC into its mint
safety reads, so `SOLANA_RPC_URL` is not required for Feed intake.

`XRAY_SOURCE=fixtures` on the intake process avoids unrelated X-ray startup
requirements; it does not replace the intake's real chain, database or history
readers. Do not add `FEED_SNAPSHOT_SLOT`, `HELIUS_RPC_URL`, user wallet credentials,
or other role keypairs to that process. Its role key must match Config's intake
signer and remain enabled. The public proxy authenticates to
`/internal/feed/attest` with `Authorization: Bearer <INTAKE_INTERNAL_TOKEN>`.

The real indexer must update `onepct:indexer:status.scanSlot` in Redis and maintain
the database mirrors used for live-card and consumed-provenance checks. Intake
rejects missing or stale indexer evidence. The freshness limit comes from
`SERVICES.indexer.maxLagSecondsForIntake`; no environment setting replaces it.

## Web build and routing

| Phase                 | Variables                                                                                                                     |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Build                 | `CLUSTER=devnet`, the same `PROGRAM_ID`, `VITE_CLUSTER=devnet`, `VITE_PREVIEW=1`, `VITE_TURNSTILE_SITE_KEY=<public site key>` |
| Railway Caddy runtime | `API_UPSTREAM=<private API host>:<public API port>`; optional `PORT`                                                          |
| Local Vite            | `VITE_API_URL=<local API origin>` or `WEB_TEST_API_URL=<local API origin>`                                                    |

Deployment identity and preview support are build-time settings. A production
build excludes demo adapters and ignores `WEB_FLOW_MODES`. Browser requests use
same-origin `/api` routes; Railway's Caddy supplies the reverse proxy. Keep the
Turnstile site configuration and `PUBLIC_WEB_URL` hostname consistent.
